Le hash = l'empreinte digitale d'un document (calculée avec SHA-256). Un seul mot change → l'empreinte change complètement. Ci-dessous : les vraies empreintes calculées par notre notebook (début…fin).

Question piège 1
« Et si le fraudeur invente un nouveau numéro de lot ? »
Lot RO-2026-9999 (inventé) arrive chez FreshMeals
↓
On cherche son historique dans le registre partagé
↓
Aucune fiche d'abattage signée → pas d'origine
↓
FreshMeals refuse le lot
Règle : 100 % des lots doivent avoir un historique signé qui remonte jusqu'à l'abattoir. Un lot sans origine est refusé.
Nouveau numéro = pas d'origine = refusé.
Question piège 2
« Et si l'abattoir écrit BEEF dès le départ, ou si on échange la viande dans le camion ? »
Tous les documents disent « BEEF »
↓
Le code compare : BEEF = BEEF → « OK »
↓
Le code ne voit rien : les documents sont cohérents… mais faux
Réponse : des tests ADN aléatoires (GenoLab) contrôlent la vraie viande. Et celui qui signe est responsable : le contrat du consortium prévoit une pénalité, puis l'exclusion.
Le code vérifie la cohérence, pas la vérité.
edit_record (modifier une fiche) : personne ne l'a. Pour corriger une erreur, on ajoute une nouvelle fiche, on n'efface jamais.
